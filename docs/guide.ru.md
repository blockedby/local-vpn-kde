## Что умеет

| Возможность | Как это работает |
| :--- | :--- |
| **Несколько профилей** | Подписки и одиночные ссылки, отдельный список серверов для каждого профиля |
| **Собственный сервер** | Добавление `vless://`, `hysteria2://` и `hy2://` прямо в TUI |
| **Проверки серверов** | Задержка, доступность выбранного сайта и скорость скачивания |
| **Режимы маршрутизации** | Строгий и умный режимы, переключение из интерфейса |
| **Управление подключением** | Запуск шлюза, подключение и отключение VPN — отдельные действия |
| **Автозапуск** | Запуск шлюза при входе в KDE, с подключением VPN по желанию |
| **Диагностика** | Состояние служб и проверки из того же интерфейса |

В native-версии выбор профиля меняет отображаемый список серверов. Применение сервера и подключение системного VPN выполняются отдельно.

## Установка

Выберите подходящий вариант:

| | Native | Docker |
| :--- | :--- | :--- |
| **Система** | Arch Linux / CachyOS, x86_64 | Ubuntu 24.04+, Debian 13+, Fedora, Arch / CachyOS, x86-64 |
| **Запуск шлюза** | Системная служба, без Docker | Контейнер Docker |
| **Способ установки** | Готовый локальный bundle | Сборка из репозитория |
| **Запуск интерфейса** | `local-vpn-kde` | `./run.sh` |

Оба варианта рассчитаны на Linux с KDE и NetworkManager. Для установки нужны интернет и права администратора.

### Native · одна команда с sudo

В каталоге доверенного bundle должны находиться `install-native.sh`, исполняемый `vpnkit-portable` и его файл контрольной суммы. Проверьте сумму, затем запустите установку **из своей обычной учётной записи**:

```bash
sha256sum -c vpnkit-portable.sha256
sudo bash ./install-native.sh
```

Установщик добавит недостающие системные зависимости, установит приложение и настроит права пользователя. Если конфигурация уже есть, подготовит профиль NetworkManager. На новой установке профиль будет создан после настройки сервера, при первом подключении.

**Установка сама не запускает и не подключает VPN.** Go, Bun и Docker на целевом компьютере не нужны. Системные компоненты — NetworkManager, его OpenVPN-плагин, OpenVPN, systemd, polkit и сетевые утилиты — устанавливаются через pacman.

Запускайте интерфейс **без sudo**:

```bash
local-vpn-kde
```

> Native bundle пока собирается локально; публичная загрузка готового релиза здесь не предполагается. Состав bundle и команды сборки: [native-установщик](portable-installer.md).

### Docker · из исходников

Установите Git через пакетный менеджер, если его ещё нет. Затем выполните **без sudo**:

```bash
git clone https://github.com/blockedby/local-vpn-kde.git
cd local-vpn-kde
./install.sh
./run.sh
```

Установщик сам запросит права администратора, установит зависимости для сборки и работы, включая Go, Bun, Docker Compose и OpenVPN, и подготовит профиль KDE.

## Первое подключение

После запуска открывается главный экран с плитками «Подключение», «Серверы», «Замеры», «Профили», «Диагностика» и «Настройки». Стрелками выберите плитку, `Enter` открывает раздел или выполняет действие подключения; `Esc` возвращает из раздела на главный экран. Вложенные окна и меню сначала закрываются по `Esc`; в таблице серверов эта клавиша сначала очищает фильтр. Строка навигации показывает путь к разделу; `Tab` / `Shift+Tab` переключают разделы «Серверы», «Профили», «Диагностика» и «Настройки».

1. Нажмите `c` и добавьте первую подписку или одиночную ссылку на сервер. После настройки установленного native `c` открывает профили.
2. Если служба остановлена, запустите её через плитку **Подключение** или `s`. Откройте **Серверы** (`v`); при необходимости обновите список (`r`).
3. Выберите строку стрелками и нажмите `Enter`. В меню доступны «Выбрать сервер», «Ping и сайт», «Скорость сервера», «Подробности сервера» и «Переименовать». Выберите **Выбрать сервер** и подтвердите выбор: по умолчанию выбрано «Нет», стрелки влево/вправо перемещают между кнопками.
4. Вернитесь на главный экран и выберите **Подключение** или нажмите `s` для подключения VPN.

**«Служба готова» ещё не означает «VPN подключён».** Служба может работать для проверок, пока системное подключение выключено.

### Всё управление — в TUI

| Клавиша | Действие |
| :---: | :--- |
| `s` / `x` | Запустить службу или подключить VPN / отключить VPN, в зависимости от состояния |
| `v` | Серверы и их проверки |
| `c` | Профили в установленном native с настроенной подпиской; иначе редактор подписки, если он доступен |
| `m` | Строгий / умный режим |
| `a` | Настройки автозапуска |
| `d` | Диагностика |
| `i` | Настройки |
| `Tab` / `Shift+Tab` | Следующий / предыдущий раздел из четырёх перечисленных выше |
| `/` | Фильтр отображаемого и исходного имени и кода страны; `Enter` сохраняет, `Esc` очищает |
| `p` / `t` | Ping и сайт / скорость и сайт показанных серверов |
| `T` / `b` | Проверить скорость сервера под курсором / предложить самый быстрый измеренный из показанных с подтверждением |
| `o` / `[` / `]` / `\` | Следующая сортировка (имя, ping, скорость, сайт, страна) / выбрать столбец / обратить направление |
| `l` | Сведения о сервере под курсором |
| `:` / `Ctrl+P` | Поиск команд |
| `j` / `k` | Задачи / отмена операции |
| `X` | Удалить активный профиль с подтверждением |
| `z` | Остановить службу или Docker вместе с VPN после подтверждения |
| `?` / `q` | Справка / выход из интерфейса |

Строка состояния показывает выбранный сервер, а нижняя строка — доступные клавиши. `a` открывает автозапуск и не выполняет ping. Проверки могут пересекаться или ожидать в очереди; `j` показывает выполняющиеся, ожидающие и завершённые операции. Доступные действия и сочетания зависят от раздела и состояния службы.

Таблица серверов показывает имя, двухбуквенный код страны, ping, скорость, доступность сайта и статус. При ширине таблицы меньше 60 символов столбец «Страна» скрыт. Сортировку можно выбрать и нажатием на заголовок столбца.

Чтобы переименовать сервер, нажмите `Enter` на его строке и выберите «Переименовать». В редакторе `Enter` сохраняет, `Esc` отменяет, пустая строка возвращает имя из подписки. Имя может содержать до 60 символов; пробелы по краям и повторяющиеся пробелы убираются. Можно сохранить до 500 переименований. В локальном файле состояния `server-names.json` хранятся идентификаторы серверов и заданные имена; они переживают обновление подписки и перезапуск и не удаляются при удалении профиля. Исходное имя переименованного сервера показано в подробностях.

Страна определяется офлайн по встроенному набору [server-country](https://github.com/sapics/ip-location-db) (общественное достояние, PDDL 1.0); адрес сервера не отправляется в сервис определения страны. Для известного IP код доступен сразу, для имени хоста может появиться после успешного ping, проверки или замера скорости. TCP ping использует адрес установленного соединения; при определении через прокси неоднозначные или неизвестные адреса не дают нового кода, а ранее определённый может сохраниться. Встроенная база — снимок данных, поэтому код может устареть.

Настройки автозапуска применяются при следующем входе в KDE. Можно запускать только шлюз либо шлюз с подключением VPN. Отключение автозапуска не разрывает текущее соединение; TUI при входе автоматически не открывается. У Docker уже работающий шлюз также может перезапускаться согласно политике контейнера.

### Если другой VPN уже подключён

Native может работать рядом с другим VPN. При подключении native обычный full-tunnel трафик получает его маршруты; более специфичные маршруты сохраняют приоритет. Чужие профили не изменяются. Если проверить маршрутизацию не удалось, откатывается только предпринятое подключение native.

Отсутствующий собственный профиль NetworkManager создаётся автоматически. Чужой или изменённый профиль не перезаписывается. Подробнее: [совместная работа VPN и защита профилей](native-coinstall.md).

## Обновление

**Native (пакет Arch или Debian), начиная с 0.4.4:**

```bash
local-vpn-kde update          # спросит подтверждение
local-vpn-kde update --check  # только проверить
```

То же есть в TUI: **Настройки → [u] Проверить обновления**. Команда берёт последний выпуск с GitHub, сверяет контрольную сумму из `SHA256SUMS`, имя, версию и архитектуру пакета и устанавливает его, только если он не тянет за собой другие пакеты. Пользователям из группы `local-vpn-kde-users` пароль не нужен. Подписи выпусков пока нет: проверка защищает от повреждённой или перепутанной загрузки, но не от подмены самого выпуска на GitHub. Перед 0.4.4 обновитесь вручную один раз (`sudo pacman -U` пакета из выпуска).

Без пакета — запустите тот же установщик из нового проверенного bundle:

```bash
sudo bash ./install-native.sh
```

Совместимые обновления приложения сохраняют работающее соединение. Переоткройте TUI, чтобы загрузить новый интерфейс. Работающий VPN-движок получит новую версию при явном перезапуске службы. Обновления системных зависимостей и переход со старых пакетов без этой поддержки имеют отдельные ограничения — см. [обновление без отключения](native-hot-upgrade.md).

**Docker:** в каталоге репозитория:

```bash
git pull
./install.sh
```

## Разработка и тестирование

Локальные проверки из корня репозитория:

```bash
go test -race ./...
mkdir -p .build
go build -o .build/local-vpn-kde.bin ./cmd/local-vpn-kde
cd scripts/vpnkit/tui
bun install --frozen-lockfile
bun run check
bun test
```

Установку и сетевые изменения проверяйте в изолированной среде:

- `test/native-arch-package-build-test.sh` — сборка и установка native-пакета в одноразовом Arch-контейнере.
- [Native E2E](native-e2e.md) — проверки NetworkManager, профилей, маршрутизации и автозапуска в выделенной VM.
- `test/vpnkit-local-install-container-test.sh --help` — Docker-установщик и сетевые проверки, требования и параметры стенда.

Тесты с настоящими подписками получают их через поддерживаемые переменные окружения, без сохранения в репозитории. Рабочие VPN, DNS и маршруты хоста не должны быть частью тестового стенда.
