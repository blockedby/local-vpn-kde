## Native gateway recovery after sleep

After a laptop woke up, Wi-Fi could have a working DHCP lease and NetworkManager could show the VPN as connected, yet no traffic passed. The gateway had lost its own routes; server and subscription refreshes could also fail.

The native gateway now checks those routes and policy rules against the current Wi-Fi or Ethernet connection. It reports missing or stale egress instead of “healthy”. NetworkManager uplink events trigger repair automatically for a running gateway; connecting or refreshing the server list also checks and repairs egress first. Restoring missing routes on the same lease does not restart the gateway or replace another VPN's routes.

**Settings → Автостарт после сна** optionally connects the VPN after wake for the current desktop user. It is off by default and independent of login autostart. If another VPN is active, automatic connection is skipped rather than taking over its routes. Gateway route repair does not depend on this setting.

**Upgrade:** run `kvpn update`, then reopen the TUI. A compatible update preserves a running tunnel. The new dispatcher and repair helper do not need a network or gateway restart; the running gateway engine uses the updated runtime at its next restart.
