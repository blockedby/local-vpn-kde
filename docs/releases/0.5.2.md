## Restart the gateway right after an update

An update keeps the VPN connected, but the running gateway kept the old version until its next restart or a reboot, and there was no simple way to restart it.

- **`kvpn update`** now asks, after installing, whether to restart a running gateway on the new version. The VPN drops for a few seconds and reconnects if it was connected. Declining keeps the old gateway running. `kvpn update --yes` still never restarts; add `--restart` to restart without asking.
- **`kvpn restart`** (also `kvpn --restart`) restarts the gateway on the installed version at any time. A stopped gateway is left alone.
- At the end of an interactive update, **Enter opens the new interface**; Ctrl+C quits. Ctrl+C now also works at the update prompts.
- **TUI:** after **Settings → [u]** installs an update, **[g] Перезапустить шлюз** appears if the gateway is running, with a confirmation. **[R] Перезапустить интерфейс** is unchanged.
- A restart that has started always runs to completion (up to 3 minutes), so cancelling it cannot leave the gateway stopped.
- README: installation from the published Arch / Debian 13 packages, an updates section and a Settings capture.

**Upgrade:** the restart offer comes from the version you update *from*, so the update to 0.5.2 itself still ends with the old message. After `kvpn update`, run `kvpn restart` once, then reopen the TUI. From 0.5.2 on, the update offers both.
